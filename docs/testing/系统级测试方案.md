# 汇智小助手系统级测试方案

## 1. 目的与原则

这次改动不是孤立功能，而是触及：

- 工具调用主链路（`execute_shell_command`、agent runtime、prompt）
- 账号身份判定（`is_admin_user`、`resolve_account_username`）
- 文件/媒体路径与账号隔离
- 数据分析账号库创建（`data_tables.connection`）
- 外部数据库/API 访问
- 代码挂载入口（`code-mount-entrypoint.sh`）
- 部署包与升级流程

因此测试不能只覆盖“沙箱能不能拦住”，必须覆盖**原有业务在改动后是否仍然成立**。
本方案按“单元 → 契约 → 集成 → 系统 E2E → 安全对抗 → 部署/升级 → 非功能”
分层，并保留与基线版本的对比，避免把历史失败误判为本次回归。

## 2. 测试环境

| 环境 | 用途 | 说明 |
| --- | --- | --- |
| 开发机 | L0/L1 单元、契约、前端组件 | 隔离的临时 HOME/工作区 |
| app 子进程集成 | L3 API 集成 | `tests/integration` 自动拉起 app |
| arm64 容器 | L4 内核沙箱、DB、网关 | `huizhi-runtime:2.2.1-arm64` |
| x86_64 容器 | 同 L4 | 需原生 Linux；QEMU 只能验证 fail-closed |
| 浏览器 | L5 UI 关键旅程 | 普通用户/admin 两套账号 |

测试数据：

- 账号：`admin`、`zhangsan`（普通）、`lisi`（普通，用于跨账号）
- 智能体：默认智能体 + 新建智能体
- 文件：普通文件、图片、zip/tar、超长文件名、中文名
- 知识空间：公共区 + 新建路径
- 数据表：CSV/Excel、SQL 查询、跨路径
- 定时任务：一次性/周期
- 外部源：本地 PG 作为第三方源、白名单 HTTP

## 7. 基线与缺陷判定

- 集成测试目前存在**历史基线失败**（provider 种子、skills pool、plugin、backup 等）。
  必须用 `git worktree` 在改动前 HEAD 上跑同一命令，比较失败集合。
- 判定：
  - 基线失败且本次仍失败 → 记为“历史问题”，不阻塞本次，但登记；
  - 基线通过、本次失败 → 本次回归，阻塞；
  - 基线失败、本次通过 → 改善，记录。
- 严重级别：
  - P0：越权/数据泄漏/普通用户可执行宿主机命令/升级丢数据
  - P1：核心业务不可用（聊天/文件/知识/数据/登录）
  - P2：功能异常但有绕行
  - P3：文案/样式/边缘
