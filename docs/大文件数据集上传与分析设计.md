# 大文件（≤10GB）上传与智能体分析：功能形态评估

- 日期：2026-11-08
- 场景：用户把 ≤10GB 的文件上传到服务器自己的路径；文件可能是压缩包，解压后是大量
  目录与文件；随后让智能体针对它做分析。
- 结论：**不要集成到聊天框**。做独立的"数据集/大文件"入口，聊天里只做"引用"。

---

## 0. 先说结论

| 方案 | 判断 |
| --- | --- |
| 直接放进聊天框附件（提高 20MB 上限） | ❌ 不可行。消息/历史/请求体都会带上文件；10GB 无法传输，也无法恢复 |
| 独立的"数据集"入口 + 聊天里引用 | ✅ **推荐**。上传、解压、清点、分析各自独立，聊天只携带 `dataset_id` |
| 上传到知识空间（现有 10GB 流式） | ◐ 仅适合"文档检索"；压缩包解压、目录树分析不是知识服务的职责 |
| 复用现有 `/api/workspace/file-upload` | ✅ 可作为 MVP 底座（已流式写入、路径限定、冲突策略），但缺断点续传/解压/清单/配额 |

**核心理由**：智能体需要的是**路径/句柄和清单**，不是 10GB 字节。把文件放进消息通道，
既传不动，也会让之后每一轮请求都背着它。

---

## 1. 现有能力与限制（已核对代码）

| 能力 | 现状 | 对 10GB 场景 |
| --- | --- | --- |
| 聊天附件 | `CHAT_UPLOAD_MAX_BYTES = 20MB`，`file.read()` 全量进内存后写 `media_dir`（`console.py:45/579`） | ❌ 上限与实现都不适合 |
| 工作区上传 | `POST /api/workspace/file-upload`：256KB 分块、`asyncio.to_thread` 写盘、路径限定到 project/workspace、冲突策略（`workspace.py:590-799`） | ✅ 可作为单请求上传底座；**没有** 大小上限、断点续传、校验 |
| 知识服务上传 | 10GB 流式、按 `space` 落盘、解析分块（`knowledge-service/main.py:254`） | ◐ 适合文档入库，不适合"解压一棵树再分析" |
| 数据分析导入 | 单文件上限 10GB、流式保存、暂存目录按账号（`data_tables/store.py:69`） | ◐ 只处理表格，不处理任意目录树 |
| 智能体读文件 | `DEFAULT_MAX_BYTES = 50KB`（`tools/utils.py:20`） | ✅ 设计正确：模型不该整文件读；需要清单/搜索/脚本工具 |
| 解压工具 | 镜像有 `unzip`/`tar`；**没有** `7z`/`rar`（`Dockerfile.base:119`） | zip/tar/gz 可用 stdlib；7z/rar 需加包或拒绝 |

## 2. 为什么不能放进聊天框

| 维度 | 聊天附件 | 独立数据集 |
| --- | --- | --- |
| 传输 | 20MB 上限；一次 multipart；断线要重传 | 分片/断点续传；10GB 可续 |
| 历史 | 文件进入消息与后续请求体 | 只留 `dataset_id` 引用 |
| 语义 | "发一条消息" | "上传一个数据集，可能解压几分钟" |
| 生命周期 | 跟会话走，删会话可能删附件 | 属于账号，可跨会话/跨智能体复用 |
| 权限 | 会话级 | 账号级，服务端按 owner 解析 |
| 解压 | 不适合在消息请求里做 | 独立 worker，可取消/重试/看进度 |
| 智能体 | 收到文件字节/解析文本 | 收到句柄，按需列目录/搜索/抽样 |

**结论**：聊天框只做"引用已上传的数据集"（一个卡片/选择器），不承载文件本身。

## 3. 推荐架构

```
浏览器 ──分片上传──▶ 数据集 API ──▶ <workspace>/datasets/<id>/source.<ext>
                                        │
                                        ▼
                                  解压/清点 worker
                                        │
                     <id>/extracted/ + <id>/inventory.json
                                        │
聊天输入框「引用数据集」──▶ 消息带 dataset_id ──▶ 智能体工具
                                                  ├─ dataset_tree
                                                  ├─ dataset_read（分页）
                                                  ├─ dataset_search（流式 grep）
                                                  ├─ dataset_stats
                                                  └─ dataset_run_script（沙箱）
```

### 3.1 API

| 端点 | 用途 |
| --- | --- |
| `POST /api/datasets/init` | 声明 name/size/sha256，返回 `dataset_id` 与分片大小 |
| `PUT /api/datasets/{id}/chunks/{n}` | 上传一个分片（幂等，可重传） |
| `POST /api/datasets/{id}/complete` | 合并、校验 sha256、落盘、入队解压 |
| `GET /api/datasets` / `GET /{id}` | 列表/状态（uploaded/extracting/ready/failed）、进度 |
| `GET /{id}/tree?path=&cursor=` | 分页列目录（不整树返回） |
| `GET /{id}/file?path=` | 单文件预览/下载（限定在 dataset 根内） |
| `DELETE /{id}` | 删除（级联清理 source/extracted/清单） |
| `POST /{id}/cancel` | 取消解压 |

### 3.2 存储布局（账号根内）

```
<workspace>/datasets/<dataset_id>/
  source.zip            # 原始文件（不可变）
  extracted/            # 解压结果（可重建）
  inventory.json        # 文件清单：路径/大小/类型/深度/计数
  meta.json             # 名称、大小、sha256、状态、错误、时间
```

- 全部在账号根目录内，复用现有 `ensure_inside_account` 的边界；
- `dataset_id` 由服务端生成（UUID），**不接受模型或客户端拼路径**；
- 配额按账号统计 `datasets/` 总大小与文件数。

### 3.3 解压与清点（独立 worker）

- 格式：zip / tar / tar.gz / tgz（stdlib）；7z/rar 需加 `p7zip`/`unar`，否则明确拒绝；
- 安全校验（每条都必须）：
  - 拒绝绝对路径、`..`、盘符；
  - 拒绝符号链接/硬链接；
  - 单文件上限、总解压上限、文件数上限、目录深度上限；
  - **压缩比上限**（zip bomb）；
  - 加密包：拒绝或要求用户提供密码（不要静默失败）；
  - 解压前检查磁盘水位；失败清理半成品；
- 清点：文件数、总大小、扩展名分布、最大文件、目录层级；写 `inventory.json`；
- 资源：独立进程/线程池、pids 上限、超时、可取消；不要把解压放在事件循环上。

### 3.4 智能体工具（关键：不传裸路径）

| 工具 | 行为 |
| --- | --- |
| `list_datasets()` | 列出当前账号的数据集（名称/大小/状态） |
| `dataset_tree(dataset_id, path, limit, cursor)` | 分页列目录；不整树进上下文 |
| `dataset_read(dataset_id, path, offset, limit)` | 文本分页读；二进制拒绝并提示 |
| `dataset_search(dataset_id, pattern, glob, max_hits)` | 服务端流式 grep，只回命中行 |
| `dataset_stats(dataset_id, path)` | 文件数/大小/类型分布（用脚本算，不读内容） |
| `dataset_run_script(dataset_id, script)` | 沙箱内跑分析脚本；数据集只读挂载，输出限流 |

所有工具：`dataset_id` → 服务端按 owner 解析根目录；不存在/不属于你返回同一错误。
**禁止**工具参数里出现任意绝对路径。

### 3.5 聊天集成

- 输入框加"引用数据集"选择器（只选，不上传）；
- 消息里渲染成数据集卡片（名称/大小/状态），请求只带 `dataset_id`；
- 可选"分析此数据集"按钮：预填一段提示（先列清单、再抽样、再给结论）；
- 数据集与会话解耦：删会话不删数据集；删数据集需确认。

---

## 4. 与第四批（每请求媒体预算/请求体恢复）的关系

两者**正交**：

- 第四批解决的是"模型请求体里携带了历史媒体，导致 413/连接断开"；
- 本场景的 10GB 文件**永远不应进入模型请求体**——智能体只拿句柄、按需读/搜/算；
- 但第四批仍然值得做：用户上传的图片/截图、历史工具输出仍会让请求体膨胀。

建议排期：第二、三批先做（shell 内存、CRLF），第四批与本场景并行；本场景的 MVP
（复用 `file-upload` + 解压 + 清单 + 3 个只读工具）可以在 2–3 周内落地。

## 5. 工作量

| 项 | 人日 |
| --- | --- |
| 数据集 API（分片/合并/校验/状态/删除） | 5–7 |

| 智能体工具（tree/read/search/stats + 归属校验） | 4–6 |
| 前端（上传页/进度/列表/引用选择器） | 4–6 |

| **合计** | **约 21–31 人日（4–6 周）** |

MVP（单请求流式上传 + 解压 + 清单 + tree/read/search + 前端入口）约 **2–3 周**；
断点续传、脚本沙箱、配额/GC 放第二阶段。

## 6. 需要你确认

1. 压缩格式：只支持 zip/tar/gz，还是必须支持 7z/rar（要加镜像依赖）？
2. 是否允许"在线解压"（落盘），还是只读压缩包内条目（不落盘）？
3. 数据集是否要跨会话、跨智能体复用？（建议是）
4. 单账号配额、保留期、磁盘水位阈值？
5. 是否需要杀毒扫描/密级标识/水印？
6. 分析脚本是否允许执行？如果允许，必须先有执行沙箱（批次 2/4 的前置）。
7. 10GB 上传是否要断点续传（浏览器刷新/网络中断后继续）？这决定是否上分片协议。
