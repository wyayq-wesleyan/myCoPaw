# 知识空间重构设计
## 2026-08-30

## 背景与目标

当前"知识空间"页面以"空间(Space)"为核心概念，用户需要先创建/选择空间再上传文档，界面左右分栏并展示检索片段。这与"非技术用户、30-50 人生产部署"的产品定位不符。

目标：**移除空间概念，所有知识文档按用户隔离**，每个用户拥有独立的个人知识空间。页面布局重构为"上查询、下列表"，上传队列可见、文件仅展示部分预览。

## 核心决策

### 1. 隐式单空间（后端隔离方式）
- 不删除 `spaces` 表，保留现有数据模型。
- 每个用户自动获取/创建**默认空间**，命名为 `user_{username}`（owner_id 为该用户）。
- 所有上传的文档统一归属该默认空间，UI 不再暴露空间选择/创建。
- 彻底移除 `POST /knowledge/spaces`、`GET /knowledge/spaces`、空间选择等前端交互。
- **API 调整**：前端调用 `listDocuments` 时不再传 `space_id`，由后端根据请求用户的 `owner_id` 隐式解析默认空间；`upload`/`search`/`query` 同理。代理层 `src/qwenpaw/app/routers/knowledge.py` 及 knowledge-service 接口均改为"从请求用户维度解析默认空间"。

### 2. 历史数据迁移
- 提供一次性迁移：把每个用户所有历史空间下的文档（含 chunks/jobs/path）迁移到该用户默认空间。
- 迁移保留文档的 `id`、`filename`、状态、处理产物；仅修改 `space_id`。
- 迁移后空间为空，不影响检索（检索按 space 过滤，合并后检索范围一致）。

### 3. 页面布局
- **上半部分：查询条件区**
  - 上传时间（RangePicker）
  - 文件名模糊查询（Input）
  - 检索问答关键词（Input，作为筛选条件）
  - 「上传资料」按钮
- **下半部分：文件列表**
  - 列：文件名、状态、上传时间、（可选）处理结果
  - 点击记录 → 查看原文（部分预览）
- **顶部：**「上传队列」按钮 → 抽屉展示任务列表

### 4. 检索问答作为筛选条件
- 输入检索词后调用现有 `POST /v1/search`（纯检索，不生成回答）。
- 取返回命中的 `document_id` 集合，文件列表**只保留这些文档**。
- 检索词、上传时间、文件名条件可同时生效（AND 组合）。
- 不展示具体片段，仅在列表显示命中文件及命中总数。

### 5. 预览：增量部分预览
- 所有格式统一为**部分预览**：只显示开头内容（约前 N 条，如 limit 100），避免大文件导致前端崩溃。
- 覆盖格式：PDF（pdfjs）、DOCX（mammoth）、文本类（txt/md/json/csv）
- **新增**：Excel（xls/xlsx/csv）以表格化展示开头部分内容。
- 预览数据来源：**新增后端接口** `/v1/documents/{id}/preview`，返回该文档开头前 N 条内容（默认 100）及结构信息；PDF/DOCX/文本沿用前端渲染，Excel/CSV 以前端表格渲染。

### 6. 上传大小限制
- 单文件必须小于 **10MB**。
- 前端在上传前校验（`file.size < 10 * 1024 * 1024`），超限提示并拦截。
- 后端校验 `KNOWLEDGE_MAX_FILE_MB=10`，超限返回 413。

## 组件拆分

### 后端（knowledge-service + proxy）

| 组件 | 职责 | 依赖 |
|------|------|------|
| `app/store.py` | 新增 `get_or_create_user_space(owner_id)` 隐式获取/创建默认空间；文档 CRUD 仍按 space_id+owner 隔离 | PG17 |
| `app/main.py` | 上传/列表/检索接口接受并忽略/隐式解析空间；提供"按用户默认空间"的默认值 | store |
| 迁移脚本 `scripts/merge_spaces.py` | 把每个用户历史空间文档合并到默认空间 | PG17 |
| 预览接口 `/v1/documents/chunks` 扩展或新增 | 返回指定文档前 N 条内容用于部分预览 | store |

### 前端（console）

| 组件 | 职责 |
|------|------|
| `pages/Knowledge/index.tsx` | 重构为"上查询、下列表"布局；移除空间选择；新增上传队列抽屉；接入部分预览 |
| `api/modules/knowledge.ts` | 移除 `listSpaces/createSpace` 使用；`listDocuments` 改为按用户默认空间；新增上传队列、部分预览接口 |

## 数据流

1. 用户进入知识空间页 → 前端调用"按用户默认空间列出文档"接口（时间/文件名/检索词筛选由前端或后端组合）。
2. 上传：前端校验 < 10MB → 调上传接口（space_id 由后端隐式解析为用户默认空间）→ 返回 queued 文档 + job。
3. 后台：worker 解析 → 提取 → 嵌入 → 入库（现有管线不变）。
4. 上传队列：轮询 jobs 表，展示文件名、状态、时间、错误。
5. 预览：点击文件 → 调部分预览接口 → 按格式渲染开头 N 条。
6. 检索问答：输入关键词 → 调 search → 命中 document_id 过滤列表。

## 错误处理
- 上传超 10MB：前端拦截 + 后端 413。
- 文件类型不支持：前端 whitelist 校验 + 后端 415。
- 查询文件列表无结果：空列表提示。
- 任务失败：列表状态显示"失败" + 错误信息。

## 测试要点
- 隐式空间：不同用户文档互不可见。
- 迁移：历史多个空间文档合并后不重复、检索正常。
- 上传队列：状态机 queued→processing→completed/failed 正确。
- 部分预览：大文件只返回开头，不崩溃。
- 检索筛选：命中 document_id 过滤正确。
- 10MB 限制：前端拦截与后端校验一致。

## 明确不做（YAGNI）
- 不删除 spaces 表、不重构检索存储。
- 不提供空间管理 UI/概念。
- 不做全量预览。
- 不新增多用户共享空间/权限。
