## 5. 未覆盖项（需现场执行）

1. **x86_64 原生 Landlock 成功路径**：本机 QEMU 不透传 Landlock，只验证了
   fail-closed。需在 x86 服务器执行：
   ```bash
   docker exec huizhi-assistant python /workspace/app/verify-isolation.py \
     --user isolation_probe --other isolation_probe_other --cleanup
   ```
2. **Oracle / Hive / MySQL 真实连通**：驱动已安装，本轮只用本地 PG 作为外部源；
   现场按实际数据源配置后，用 `huizhi_gateway.query` 抽查一次。
3. **多天/大数据量压力**：本轮为功能与边界测试，未做长时间稳定性/容量压测。
4. **常驻服务**：按当前需求不纳入。
5. **旧 `.sandbox-owner` v1 marker 升级**：代码会重新全量 chown，但未在真实
   7GB 账号目录上计时；首次执行可能较慢，建议在低峰期做第一次 shell 调用。

## 6. 结论

本轮改动满足“账号级隔离”的验收条件：

- 普通用户只能读写自己的数据；
- 自己的 PG 库可读写，跨库/平台库/应用超级用户角色被拒绝；
- 第三方 DB/API 通过受控网关，只读 SQL + host 白名单；
- 无网络、无应用源码、无密钥；
- 资源、审计、并发、失败关闭均通过；
- 未发现 FAIL 项。

正式上线前仍需在目标 x86 服务器执行同一套验证，并抽查 Oracle/Hive/MySQL
实际数据源。
