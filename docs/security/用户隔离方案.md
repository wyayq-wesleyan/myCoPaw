# 普通用户隔离改造（Linux 沙箱）

## 1. 角色模型

只有两种角色，不再引入“高级用户”：

| 角色 | 能力 |
| --- | --- |
| `admin` | 管理账号/模型/工具；`execute_shell_command` 直接运行；可使用外部智能体、桌面截图、浏览器 |
| `user` | 只能访问自己账号的数据；`execute_shell_command` 强制进入沙箱；外部智能体/桌面截图/浏览器由后端拒绝 |

角色判断在后端工具入口完成，不依赖前端菜单或智能体配置。普通用户即使自己勾选了
高风险工具，调用时也会被拒绝或降级到沙箱。

## 2. 普通用户 shell 沙箱

### 2.1 内核层

- **Landlock**（Linux 5.13+）：路径白名单。允许读系统运行库和本账号根目录；
  只允许写本账号 `outputs/` 和 `scripts/`。
- **seccomp**（libseccomp）：禁止非 `AF_UNIX` socket，禁止 io_uring、bpf、ptrace、
  mount/unshare/chroot、mknodat、open_by_handle_at 等逃逸原语。
- **独立 UID/GID**：每个账号一个确定性的非 root UID（20000–99999），
  `outputs/`、`scripts/` 归该 UID 可写；`media/`、`upload/` 归该 UID 可读。
- **rlimit**：地址空间（默认 16GB）、CPU 时间、单文件大小（默认 4GB）、
  打开文件数、进程数（默认 512）。

### 2.2 可见路径

| 路径 | 权限 |
| --- | --- |
| 本账号工作区（含 `media/`、`upload/`、`agents/*/media`） | 只读 |
| 本账号 `outputs/`、`scripts/` | 读写 |
| `/usr`、`/lib`、`/bin`、`/sbin`、`/etc`、`/dev` | 只读/执行（`/dev` 可写设备节点，但 seccomp 禁止创建新节点） |
| `/workspace/app`（应用源码） | 不可见 |
| `/app/working.secret` | 不可见 |
| 其他账号目录 | 不可见 |
| `/data`、`/proc`、`/sys`、`/tmp` | 不可见 |

### 2.2.1 可读路径的风险评估

| 路径 | 为什么放开 | 残余风险 | 结论 |
| --- | --- | --- | --- |
| 本账号工作区（含 `agents/*/media`、`upload/`） | 用户自己的文件、对话上传、解压产物 | 同一账号内多个智能体互相可见；不是跨用户泄漏 | 账号级隔离符合要求；若要做“智能体之间也隔离”需另做 per-agent 授权 |
| `/usr`、`/lib`、`/bin`、`/sbin` | Python 解释器、第三方库、动态库、常用命令 | 第三方包源码/文档可读；不能写；应用源码已从 site-packages 删除 | 保留；这是运行 Python 数据栈的必要条件 |
| `/etc` | `passwd`/`group`/`nsswitch`/`ld.so`/字体/时区等运行配置 | `/etc/shadow`、`/etc/gshadow`、`/etc/sudoers`、`/etc/ssl/private` 由 DAC 保护；未来若有人把密钥放进 world-readable 的 `/etc` 会泄漏 | 保留但只读；运维禁止把密钥写入 `/etc` |
| `/dev` | `/dev/null`、`/dev/urandom`、`/dev/shm`、PTY | 设备 cgroup 只暴露安全设备（无 `/dev/mem`、`/dev/sda`、`/dev/kmsg`）；`/proc` 不可见；`mknodat` 与 `mq_*` 被 seccomp 禁止；`/dev/shm` 默认 64MB，仍可能被单个沙箱填满 | 保留；DoSV 风险有容器 cgroup 兜底 |

> Landlock 的 path-beneath 规则只能按**目录**授权，不能单独授权 `/etc/passwd` 这类文件，
> 也不能只授权 `/dev/null`。要做到“最小 /etc、最小 /dev”必须引入 mount namespace
> （bwrap/nsjail），那是下一阶段的镜像改造。

### 2.3 环境变量

沙箱进程使用白名单环境，不继承 `os.environ`：

- 只传 `PATH`、`HOME`、`TMPDIR`、`LANG`、`TZ` 等安全变量；
- 不传 `QWENPAW_*`、`KNOWLEDGE_*`、`DATABASE_URL`、`*_KEY`、`*_TOKEN`、`*_SECRET`；
- `HOME`/`TMPDIR`/缓存目录都指向 `outputs/` 下，沙箱不会写工作区其他位置。

### 2.4 失败策略

沙箱不可用（内核无 Landlock、无 libseccomp、初始化失败）时：

- 普通用户：**拒绝执行**，返回明确错误；
- 不存在“回退到宿主机 shell”的路径；
- admin 不受影响。

### 2.5 审计

每次普通用户 shell 执行都会追加一条 JSONL 记录到：

```text
<QWENPAW_LOG_DIR>/sandbox-audit.jsonl
# 默认：/app/working/logs/sandbox-audit.jsonl
```

文件权限 `0600`，只对 root/admin 可读；沙箱的 Landlock 白名单不包含该目录。
记录字段：时间、账号、UID、cwd、命令（超过 16KB 截断）、完整命令 SHA256、
退出码、耗时、超时、违规信息、stdout/stderr 字节数。文件超过 20MB 轮转为
`sandbox-audit.jsonl.1`。审计写入失败只记日志，不影响命令执行。

## 3. 高风险工具

以下工具后端强制 admin-only：

- `delegate_external_agent`（外部 ACP 智能体）
- `desktop_screenshot`（桌面截图）
- `browser`（浏览器自动化）

`execute_shell_command` 对普通用户保留，但必须经过上述沙箱。其他文件/知识/数据工具
继续使用账号根和路径 grants 校验。

## 4. 应用源码清理

代码挂载入口脚本在启动时删除镜像 `site-packages` 里的 `qwenpaw` 副本：

- 应用进程通过 `PYTHONPATH=/workspace/app/src` 使用挂载代码；
- 沙箱虽然可以读 `/usr`，但读不到应用源码；
- 只在检测到挂载代码存在时删除，镜像模式回滚不受影响。

## 4.1 自己的 PostgreSQL（读写）

普通用户 shell 自带标准 `PG*` 环境变量：

```text
PGHOST=/app/working/workspaces/<account>/outputs/pgsock
PGPORT=5432
PGUSER=sbx_<hash>
PGPASSWORD=<每账号随机>
PGDATABASE=<该账号数据库>
```

- `psycopg2.connect()`、`psql`、pandas 直接可用；
- 在该账号数据库内可以 SELECT / INSERT / UPDATE / DELETE / TRUNCATE，
  可以建自己的表/视图/函数；
- 应用管理的表可以被读写，但不授予 DROP/ALTER（避免一次脚本把应用表结构改坏）；
  需要新结构时在自己的 schema/表里实现；
- 不能访问平台库 `huizhi_knowledge`、知识图谱库或其他账号数据库；
- 实现方式：每账号一个非 superuser PG role + UNIX socket 代理；代理解析
  PostgreSQL StartupMessage，只接受该账号的 role/database 对，应用超级用户
  密码也不能拿来穿过代理；
- `PUBLIC` 的 CONNECT 已在所有库撤销，新库在创建时也会撤销（包括
  `data_tables.connection` 创建账号库的路径）。

## 4.2 第三方数据库 / API（只读网关）

沙箱没有 TCP 网络。第三方访问统一走本机 UNIX socket 网关：

```text
<SECRET_DIR>/sandbox-external-sources.json   # 管理员维护，0600
/app/working/workspaces/<account>/outputs/gateway.sock
/app/working/workspaces/<account>/scripts/huizhi_gateway.py  # 客户端
```

配置示例：

```json
{
  "sources": {
    "erp_pg": {
      "type": "postgres",
      "host": "10.0.0.5",
      "port": 5432,
      "database": "erp",
      "user": "readonly",
      "password": "...",
      "allow_all": true
    },
    "oa_oracle": {
      "type": "oracle",
      "dsn": "10.0.0.6:1521/OA",
      "user": "readonly",
      "password": "...",
      "allowed_users": ["zhangsan"]
    }
  },
  "http_allow": ["api.example.com", "*.example.org"]
}
```

支持类型：`postgres`、`mysql`/`mariadb`、`oracle`、`hive`。
用户代码：

```python
import os, sys
sys.path.insert(0, os.environ["HUIZHI_SCRIPTS_DIR"])
import huizhi_gateway

huizhi_gateway.sources()
rows = huizhi_gateway.query("erp_pg", "SELECT * FROM orders LIMIT 10")
resp = huizhi_gateway.http("GET", "https://api.example.com/health")
```

约束：

- 第三方 SQL **只读**：单条 SELECT/WITH，禁止写操作、数据修改 CTE、文件函数；
- 每个 source 必须 `allow_all: true` 或 `allowed_users` 明确授权，否则拒绝；
- HTTP 只允许 `http_allow` 中的 host，禁止重定向，响应上限 2MB；
- 连接串/密码只存在 `SECRET_DIR`，沙箱读不到；
- 网关调用写入 `sandbox-audit.jsonl`（source、SQL/URL 的 SHA256、行数/状态）。

## 5. 部署要求

默认配置（推荐，openEuler 5.10/24.03 可用）：

```text
HUIZHI_SANDBOX_LANDLOCK=0
```

- 使用 UID/组权限 + seccomp 沙箱；
- 账号根 `root:<gid> 2750`，A 的进程不能进入 B 的目录；
- `outputs/`、`scripts/` 组可写，`media/`、`upload/` 只读；
- `chats.json`、`credentials.yaml`、`app` 源码、日志、备份、`working.secret`
  收为 root 0700；
- 需要 `libseccomp.so.2`，用于禁网络/挂载/ptrace；
- 应用以 root 启动（创建账号 UID、收紧权限）；
- 不需要 `--privileged`、不需要 `CAP_SYS_ADMIN`、不需要 Docker socket。

只有确认内核满足以下条件时，才改成 `HUIZHI_SANDBOX_LANDLOCK=1`：

- Linux kernel ≥ 5.13；
- `/boot/config-$(uname -r)` 中 `CONFIG_SECURITY_LANDLOCK=y`；
- `/sys/kernel/security/lsm` 包含 `landlock`；
- 镜像内有 `libseccomp.so.2`。

该配置为 1 但内核不支持时，普通用户 shell **失败关闭**，不会退回权限沙箱。
修改后必须重建主应用容器，不是 `docker restart`。

检查命令：

```bash
uname -r
grep CONFIG_SECURITY_LANDLOCK /boot/config-$(uname -r)
grep landlock /sys/kernel/security/lsm
ldconfig -p | grep libseccomp
```

## 6. 已知边界

- 沙箱默认**无网络**：用户代码不能访问互联网、局域网、数据库、知识服务；
  需要数据/知识能力时使用受控的 `data_tables`、`query_knowledge` 工具。
- 长驻服务（用户代码起 HTTP 服务）在无网络命名空间下对外不可达；需要独立
  per-user service container 才能支持，属于下一阶段。
- `HUIZHI_SANDBOX_LANDLOCK=0` 时没有 Landlock 的全局文件系统视图隔离：
  系统文件（`/etc`、`/usr`）仍可读，`/tmp` 仍可写（进程 umask 077）；
  账号之间的数据由组权限隔离，不共享同一 GID。
- PostgreSQL 仍是共享实例、共享应用账号；per-user DB role/RLS 尚未实现。
- 资源限制是进程级 rlimit；容器级 cgroup 仍是最外层兜底。
- 首次沙箱执行会一次性把整个账号根 chown 给沙箱 UID（marker `v2:` 控制），
  以后新增文件按应用默认 umask 644/755；历史 0600 文件会被修正为可读。
- 审计是文件级 JSONL，还没有管理界面；管理员通过日志目录查看/归档。
