# 普通用户隔离测试方案

## 1. 目标

覆盖这次改动涉及的全部边界：

- 账号文件系统隔离（media/upload/output、其他账号、应用源码、密钥）
- Linux 沙箱（Landlock + seccomp + 独立 UID + rlimit）
- 账号 PostgreSQL 读写与跨库拒绝
- 第三方数据库/API 网关
- 审计、失败关闭、并发、升级兼容
- ARM64 实机验证；x86_64 原生验证步骤

## 2. 测试分层

| 层 | 内容 | 执行位置 | 自动化 |
| --- | --- | --- | --- |
| L0 | 纯单元测试：路径生成、SQL guard、角色命名、配置权限、审计格式 | 开发机 | pytest |
| L1 | 全量后端回归 | 开发机 | pytest tests/unit |
| L2 | 沙箱真实内核测试 | app 容器（Linux） | `verify-isolation.py` |
| L3 | 数据库真实权限测试 | app 容器 + PG | `verify-isolation.py` |
| L4 | 外部网关测试 | app 容器 + 本地 PG/HTTP | `verify-isolation.py` |
| L5 | 失败模式与并发 | app 容器 / QEMU | 脚本 + 手工 |
| L6 | 升级兼容与启动 | 测试 app 容器 | 手工 |
| L7 | x86_64 原生 | x86 服务器 | 待现场执行 |

## 4. 执行命令

```bash
# L0/L1
cd <repo>
PYTHONPATH=src .venv/bin/python -m pytest tests/unit -q

# L2-L4：在 app 容器内，使用专用探测账号（不要用真实业务账号）
docker exec huizhi-assistant python /workspace/app/verify-isolation.py \
  --user isolation_probe --other isolation_probe_other --cleanup
```

`verify-isolation.py` 会创建/覆盖探测账号下的 `media/m.txt`、`upload/u.txt`、
`note.txt`，因此**只能对专用探测账号执行**；`--cleanup` 只允许
`isolation_probe*` / `verify_*` 账号，防止误删真实账号库。

外部网关测试需要 `sandbox-external-sources.json`（0600），并允许 `127.0.0.1`
以测试本地 HTTP；没有配置时相关用例 SKIP。

## 5. 通过标准

- 全量单元测试无新增失败；
- `verify-isolation.py` 的必需用例全部 PASS，FAIL=0；
- 失败模式下普通用户得到 DENIED / 功能降级，不得回退宿主机；
- 并发用例无串号、无跨账号读取；
- x86_64 现场执行同一脚本通过。
