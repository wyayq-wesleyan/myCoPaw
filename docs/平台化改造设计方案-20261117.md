# 汇智小助手平台化改造设计方案

> 依据 `console/design-lab` 当前原型整理，用于指导后续生产代码改造。
> 目标：把现有「通用 AI 助手」改造为「面向案件业务的政务工作台」，同时保持既有目录结构、数据隔离与部署方式不变。

---

## 一、改造总览

### 1.1 现状与目标的差距

| 维度 | 现状 | 目标 |
|---|---|---|
| 入口 | 单一对话页，全部能力混在一起 | 首页四模块 + 独立工作区，业务与办公分离 |
| 身份 | 本地账号 + 可选管理员 | 统一身份平台登录，角色由平台下发 |
| 业务上下文 | 无案件概念，仅靠路径名区分 | 案件为一等公民：案件树、在控目标、案件空间 |
| 权限判定 | 路径授权 + 工具级策略 | 案件/目标/查询批次三级，权限由查询中心判定 |
| 审批 | 工具执行审批（本地 Future） | 业务审批：查询批次 → 审批系统 → 回调 → 结果入库 |
| 智能体 | 用户自由创建，配置分散 | 系统预设由管理员维护，用户复制为自定义后调优 |
| 知识 | 账号级知识空间，按路径分文档 | 智能体级知识空间 + 案件空间并存，只读挂载不复制 |
| 文件 | 工作区文件树 | 案件空间文件树（可建目录/移动）+ tmp/res 固定区 |
| 会话 | 会话抽屉，绑定智能体 | 会话跟随案件+智能体，右侧历史或输入区切换 |

### 1.2 设计原则

1. **路径结构不变**：继续使用 `/data/huizhi-assistant`、`/data/knowledge-service`、`/postgres-data`。
2. **复用现有能力**：`/paths`、`/knowledge`、`/mcp`、`/agents`、`/workspace`、`/chats` 六大路由已覆盖 80% 后端需求。
3. **权限判定外置**：小助手不做权限判断，查询中心（MCP Server）判定，审批系统流转。
4. **只读挂载优于复制**：智能体知识只存一份，避免重复解析和版本漂移。
5. **不可变快照**：智能体任何保存都生成新记录，历史会话可复现。

## 二、信息架构

### 2.1 顶层导航

```text
首页
├── 办公助手            # 非案件，所有角色可用
├── 信息核查            # 案件业务（一期重点）
├── 档案经营            # 长期经营（二期）
├── 信息监测            # 持续监测（二期）
├── 智能体管理          # 管理入口（顶栏）
└── 通知中心            # 审批/任务/通知（顶栏）
```

首页只做模块入口，不设全局对话。最近会话置于问候语下方。

### 2.2 信息核查工作区

```text
┌──────────────┬──────────────────────────────┐
│ 左侧栏        │ 中间工作区                     │
│              │                              │
│ Tab: 案件     │ 案件标题 + 在控目标摘要          │
│  - 案件详情   │ 对话流                        │
│  - 切换案件   │  - 工具调用步骤                │
│              │  - 查询结果卡                  │
│ Tab: 在控目标  │  - 无权限决策卡                │
│  - 分页列表   │  - 查询审批请求条              │
│  - 每次刷新   │ 输入区                        │
│              │  - 会话选择 / 新建 / 附件       │
│ Tab: 文件树   │  - 上下文 / 模型 / 发送         │
│  - 目录树     │ 悬浮导航：到顶 / 聊天记录 / 到底  │
│  - tmp/res   │                              │
└──────────────┴──────────────────────────────┘
```

右侧不再有独立栏；会话选择在输入区右侧、上下文用量左侧。

### 2.3 办公助手

```text
┌──────────────┬──────────────────────────────┐
│ 办公空间概览   │ 办公对话                      │
│ 资料/临时/结果 │ 气泡 / 工具 / 表格              │
│              │                              │
│ 文件树        │ 输入区（同核查页）              │
│  - 目录操作   │                              │
│  - 上传/删除  │                              │
└──────────────┴──────────────────────────────┘
```

办公空间与案件空间完全隔离，不出现知识空间、数据空间独立页面。

### 2.4 智能体管理

- 列表 / 卡片双视图，6 条/页
- 搜索、模块筛选、仅显示可用
- 管理员：多选、批量删除、复制、删除
- 普通用户：预设只读、复制为自定义、使用；自定义可改、可删

### 2.5 智能体详情（三栏）

```text
┌────────────┬──────────────────┬──────────────┐
│ 资源菜单    │ 问答调试           │ 智能体信息     │
│ 知识空间    │ 气泡流             │ 名称/模块/模型 │
│ 技能        │ 悬浮导航           │ 资源数量       │
│ 工具        │ 输入工具栏         │ 提示词摘要     │

└────────────┴──────────────────┴──────────────┘
```

## 三、领域模型

### 3.1 核心实体

```text
User（平台账号）
  ├─ roles: 管理角色 / 业务角色
  └─ cases: 有权限的案件（由 TCMS 决定）

Case（案件，来自 TCMS）
  ├─ code / name / type / status / org / owner
  ├─ targets: 在控目标
  └─ path_id: 对应平台路径节点（一个案件一个路径）

Target（在控目标）
  ├─ type: 手机号 / 身份证 / 车牌号
  ├─ value / name / status
  └─ source: 案件在控 / 用户输入

Agent（智能体）
  ├─ scope: system（预设） / custom（自定义）
  ├─ owner: 系统 或 用户名
  ├─ base_agent_id: 复制来源
  ├─ knowledge_space_id: 智能体专属知识空间
  ├─ skills / tools / mcp_clients
  └─ prompt / model

Session（会话）
  ├─ case_id + agent_id
  ├─ chat_id（ChatSpec）
  └─ project_dir: 案件工作目录

QueryBatch（查询批次）
  ├─ batch_id
  ├─ targets: 本批次目标
  ├─ permission: 全部在控 / 需审批
  └─ approval_flow_id

ApprovalFlow（审批流程，TCMS）
  ├─ flow_id / batch_id
  ├─ status: 审批中 / 已通过 / 已驳回
  └─ callback_at
```

### 3.2 关键关系

| 关系 | 基数 | 说明 |
|---|---|---|
| 案件 → 路径 | 1:1 | 案件在平台存储中对应一个路径节点 |
| 案件 → 在控目标 | 1:N | 目标归属案件，跨案件不可见 |
| 案件 → 会话 | 1:N | 同一案件可多会话 |
| 智能体 → 会话 | 1:N | 同一智能体可多会话 |
| 会话 → 智能体 | N:1 | 会话固定绑定一个智能体快照 |
| 智能体 → 知识空间 | 1:1 | 每个智能体一个专属知识空间 |
| 查询批次 → 目标 | 1:N | 一次查询的所有目标 |
| 查询批次 → 审批 | 1:1 | 需审批时一个批次一个流程 |

## 四、后端改造

### 4.1 复用现有路由（无需新建）

| 能力 | 现有路由 | 复用方式 |
|---|---|---|
| 路径树/创建/移动/删除 | `GET/POST/PATCH/DELETE /paths` | 案件与文件树直接映射为路径节点 |
| 路径资源绑定 | `/paths/{id}/resources` | 知识文档、数据表绑定到案件路径 |
| 智能体路径授权 | `/paths/agent-grants` | 决定智能体可见哪些案件空间 |
| 知识上传/重解析/删除/原文 | `/knowledge/documents/*` | 增加 `agent_id` 维度即可 |
| 文档列表/分页/状态 | `GET /knowledge/documents` | 增加 scope 过滤 |
| MCP 客户端 CRUD | `/mcp/clients` | 直接作为「查询客户端」配置 |
| MCP 工具与访问策略 | `/mcp/.../tools`、`/access` | 沿用 |
| 智能体 CRUD/复制 | `/agents`、`/agents/{id}/copy` | 增加 scope 与复制语义 |
| 工作区文件树/上传/下载 | `/workspace/tree`、`/workspace/upload` | 案件文件树复用 |
| 会话 CRUD/归档/导入导出 | `/chats` | 复用 |

### 4.2 需要新增的能力

#### （1）案件聚合接口

前端不应该自己拼接 TCMS + 路径 + 知识 + 数据表。新增一层 BFF：

```http
GET /api/cases                     # 有权限案件列表（透传 TCMS）
GET /api/cases/{code}              # 案件详情
GET /api/cases/{code}/targets      # 在控目标（每次实时查询 TCMS）
GET /api/cases/{code}/files/tree   # 案件文件树（= /paths 子树 + workspace）
POST /api/cases/{code}/files/upload
POST /api/cases/{code}/files/mkdir
POST /api/cases/{code}/files/move
DELETE /api/cases/{code}/files
```

**为什么需要 BFF**：案件权限、路径映射、TCMS 字段翻译都在服务端完成，前端只做展示；避免前端持有 TCMS token 或自行判断权限。

#### （2）查询批次与审批

```http
POST /api/query-batches            # 创建批次（目标列表）
GET  /api/query-batches/{id}       # 批次状态
POST /api/query-batches/{id}/approval   # 发起审批（调 middleware）
POST /api/query-batches/{id}/terminate  # 终止本批次
```

批次状态机：

```text
created
  ├─ 全部在控 → querying → completed
  └─ 存在非在控 → pending_approval
                     ├─ approved → querying → completed
                     ├─ rejected → rejected
                     └─ terminated → terminated
```

审批发起后由 middleware 调 TCMS，回调地址：

```http
POST /api/approvals/callback
{
  "flow_id": "...",
  "batch_id": "...",
  "status": "approved" | "rejected",
  "approved_at": "..."
}
```

回调后触发本批次查询，结果入库并写入会话。

#### （3）智能体级知识空间

知识服务扩展（不是新建库）：

```sql
ALTER TABLE spaces ADD COLUMN scope TEXT NOT NULL DEFAULT 'user';  -- user | agent
ALTER TABLE spaces ADD COLUMN agent_id TEXT;
ALTER TABLE documents ADD COLUMN scope TEXT NOT NULL DEFAULT 'user';
ALTER TABLE documents ADD COLUMN agent_id TEXT;

CREATE INDEX idx_spaces_agent ON spaces(agent_id) WHERE scope = 'agent';
CREATE INDEX idx_documents_agent ON documents(agent_id) WHERE scope = 'agent';
```

向量工作区命名：

```text
用户/案件文档：ws_<path_uuid_hex>          （现有）
智能体知识：  ws_agent_<agent_id_hex>      （新增）
```

检索时两路合并：

```text
allowed_workspaces = ws_<案件路径> + ws_agent_<当前智能体>
allowed_documents  = 账号路径内文档 ∪ 该智能体知识文档
```

这样：
- 智能体知识只解析、向量化一次；
- 管理员更新后所有使用者立即生效；
- 用户无法修改智能体知识；
- 案件产生的文件仍写自己的路径。

#### （4）智能体复制语义

```http
POST /api/agents/{agent_id}/copy
{
  "name": "可选",
  "scope": "custom"        # 普通用户复制固定 custom；管理员可复制为 system
}
```

复制内容：
- 智能体配置（prompt、model、skills、tools）
- MCP 客户端配置
- 知识空间**引用**（不复制文档，新智能体指向同一知识空间或新建空空间）

> 建议：普通用户复制时新建空知识空间，由用户自行上传；避免用户副本继承全部预设知识造成空间膨胀。管理员复制为系统预设时共享原知识空间。

### 4.3 需要调整的现有逻辑

| 位置 | 调整 |
|---|---|
| `agents/tools/knowledge.py::_workspaces_for_agent` | 追加 `ws_agent_<agent_id>` |
| `agents/tools/knowledge.py::query_knowledge` | 可检索文档集合加入智能体知识 |
| `agents/tools/path_scope.py` | 增加“案件空间”与“智能体知识”两类来源的区分提示 |
| `runtime/prompt_contributors.py` | 增加案件上下文、查询批次、审批语义 |
| `app/routers/paths.py` | 路径创建时允许标记 `kind: case|folder` |
| `app/routers/knowledge.py` | 上传参数增加 `agent_id`（scope=agent 时） |

**智能体**

- 复制后提示“已复制为自定义智能体”

## 六、权限模型

### 6.1 角色

| 角色 | 来源 | 能力 |
|---|---|---|
| 管理角色 | 平台 MSP | 智能体、知识空间、MCP 客户端维护；可进入业务 |
| 业务角色 | 平台 MSP | 案件业务、办公助手、使用智能体 |

不再有本地 admin 账号；原型默认账号带管理角色。

### 6.2 数据隔离矩阵

| 资源 | 隔离维度 | 判定点 |
|---|---|---|
| 案件 | 账号 + TCMS 授权 | BFF + TCMS |
| 在控目标 | 案件 | 查询中心 |
| 文件 | 账号 + 案件路径 | `/workspace` 路径校验 |
| 知识文档（用户） | 账号 + 路径 + 智能体授权 | `visible_document_ids` |
| 知识文档（智能体） | 智能体 scope | `scope=agent` 过滤 |
| 数据表 | 账号 PG schema + 路径 | `data_tables` 工具 |
| 会话 | 账号 + 智能体 workspace | `/chats` owner 校验 |
| MCP 客户端 | 智能体 | `/mcp` agent 上下文 |

### 6.3 审批边界

```text
用户发起查询
  → 小助手创建查询批次（目标列表）
  → 查询中心逐目标判定是否在控
      ├─ 全部在控 → 直接查询
      └─ 存在非在控 → 返回 needs_approval
            → 用户选择：终止 / 发起审批
            → 小助手调 middleware 创建 TCMS 流程
            → 用户在新标签填写审批表单
            → 上级审批
            → TCMS 回调 middleware
            → middleware 回调小助手（/api/approvals/callback）
            → 本批次所有目标统一查询
            → 结果入库 + 会话展示
```

小助手不判断目标是否在控，只负责展示与流程串联。

## 七、知识空间落地方案

### 7.1 三种知识来源

| 来源 | 归属 | 写入 | 读取 |
|---|---|---|---|
| 智能体知识 | 智能体 | 管理员 | 所有使用者只读 |
| 案件知识 | 案件路径 | 案件成员 | 该案件智能体 |
| 公共知识 | 账号根路径 | 账号本人 | 授权智能体 |

### 7.2 为什么不做复制

复制会导致：
1. 同一文档 N 次解析、N 份向量；
2. 管理员更新后旧副本不生效；
3. 用户可改坏“标配”；
4. 存储随用户数线性增长。

只读挂载只有一份源，改完即生效，符合“系统预设由管理员统一维护”。

### 7.3 文档状态与处理链路

```text
上传 → queued → parsing → chunking → embedding → completed
                                        └─ failed（可重试）
```

前端展示：
- 待解析 / 解析中（进度）/ 向量化中（进度）/ 已就绪（片段数）/ 解析失败
- 管理员操作：解析、重新向量化、删除
- 删除文档时同步清理向量与图谱

### 7.4 检索合并规则

```python
allowed_workspaces = path_workspaces(agent) + [agent_workspace(agent_id)]
allowed_documents  = path_documents(agent) + agent_documents(agent_id)
```

两路结果合并后按相关度排序，引用中标明来源（智能体知识 / 案件知识）。

## 八、文件与预览

### 8.1 预览链路（复用现版本）

```text
点击文件
  → GET /api/files/preview/{path}        二进制流（含鉴权）
  → 前端按扩展名选择渲染器
      ├─ 图片：<img> blob
      ├─ PDF：<embed> / pdfjs
      ├─ Markdown：react-markdown
      ├─ Word：mammoth
      ├─ Excel/CSV：xlsx / 表格
      ├─ JSON/文本：代码块
      └─ 其它：下载
```

现版本 `console/src/pages/Coding/FilePreview.tsx` 已实现上述分流，直接复用即可。

### 8.2 案件文件树映射

| 树节点 | 实际路径 | 说明 |
|---|---|---|
| 案件 X | `<user_root>/cases/<case_code>` | 案件根 |
| 案件材料 | `.../materials` | 只读或案件成员可写 |
| 上传文件 | `.../uploads` | 用户上传 |
| tmp | `.../tmp` | 智能体临时文件，固定 |
| res | `.../res` | 智能体结果文件，固定 |

`tmp` / `res` 由系统创建，前端不允许改名、删除、移出。

### 9.1 版本号

现有 `VERSION`、`app/VERSION`、`knowledge-service/VERSION` 机制保留，新增：


前端顶栏或设置页展示，便于多服务器比对。

### 9.2 数据库迁移

| 迁移 | 内容 | 兼容性 |
|---|---|---|
| P1 | `paths` 增加 `kind`（case/folder） | 默认 folder，旧数据不受影响 |

### 9.3 迁移步骤

1. 备份数据库与 `.env`
2. 停应用容器（知识服务可不停）
3. 执行迁移 SQL
4. 更新代码（挂载方式，不重建镜像）
5. 启动并验证 `/api/version`、`/api/healthz`
6. 抽查：旧会话可打开、旧知识文档可检索、旧文件可预览

## 十一、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| TCMS 接口不稳定 | 案件/目标加载失败 | BFF 缓存 + 明确错误提示 + 重试 |
| 审批回调丢失 | 批次卡在审批中 | 定时补偿查询 TCMS 状态 |
| 知识 scope 迁移出错 | 文档不可见 | 默认 user + 双写校验 + 回滚脚本 |
| 智能体复制导致知识膨胀 | 存储增长 | 复制默认新建空知识空间 |
| 前端路由变更 | 旧书签失效 | `/chat` 重定向 + 保留旧路径 |
| 大文件预览卡顿 | 体验差 | 分片/懒加载，超大文件走下载 |

## 十二、验收清单

### 功能

- [ ] 统一身份登录，无本地管理员入口
- [ ] 管理角色可维护智能体，业务角色只读预设
- [ ] 案件树仅展示有权限案件
- [ ] 在控目标每次进入刷新
- [ ] 文件树可建目录、移动、多选删除，tmp/res 不可改
- [ ] 点击文件可预览
- [ ] 查询批次返回无权限时可终止或发起审批
- [ ] 审批通过后本批次统一查询并展示结果
- [ ] 智能体复制为自定义后可调优、可调试
- [ ] 智能体知识上传后可解析、向量化、检索
- [ ] 会话按案件+智能体隔离
- [ ] 悬浮导航到顶/到底/聊天记录可用

### 非功能

- [ ] 旧数据升级后可用
- [ ] 路径结构未改变
- [ ] `/api/version` 可查
- [ ] 权限越权测试通过（跨账号、跨案件、跨智能体）
- [ ] 审批回调幂等
- [ ] 知识删除同步清理向量

## 十三、需要确认的事项

1. **TCMS 接口清单**：案件列表、详情、在控目标、审批发起、审批回调的字段与鉴权方式。
2. **查询中心协议**：批次请求/响应结构，`needs_approval` 字段定义。
3. **middleware 审批接口**：发起流程、回调地址、幂等键。
4. **智能体知识复制策略**：复制时新建空知识空间，还是共享原空间（建议前者）。
5. **是否需要知识版本快照**：若审计要求还原历史回答依据，需增加 `agent_knowledge_versions` 表。

以上确认后即可进入一期开发。
